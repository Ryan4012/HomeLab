## What I Did
- Spun up a Debian 13 LXC on Proxmox to host Gitea, and installed it manually — binary, dedicated system user, systemd service, SQLite backend.
- Created 4 repos to start: terraform-homelab, ansible-homelab, k3s-manifests, ci-pipelines.
- Set up SSH key auth so I could push/pull without password prompts.
- Installed Terraform and Ansible directly on the Gitea LXC rather than my personal laptop, keeps the tooling with the automation instead of scattered across machines.
- Built a Debian 13 cloud-init template on Proxmox (VM ID 9000) so Terraform could clone new VMs on demand instead of installing from ISO every time.
- Created a dedicated Proxmox API user/role/token scoped specifically for Terraform, instead of using my main Proxmox login.
- Wrote the actual Terraform config — variables, provider block, and resource definitions to clone the template into two VMs (k3s-server-01, k3s-agent-01), injecting static IPs and my SSH key via cloud-init.
- Ran terraform plan → reviewed it → terraform apply — both VMs came up clean.
- Wrote an Ansible inventory and playbook to install k3s on the server, pull the generated node token, and join the agent to it — automating what would otherwise be manual copy-pasting between machines.
- Verified the cluster with kubectl get nodes — both nodes Ready.
- Installed kubectl on the Gitea LXC and pulled the kubeconfig so I can manage the cluster without SSHing into the server node directly.
- Committed the working Terraform and Ansible configs to their Gitea repos.
- Enabled Gitea Actions, installed act_runner in host mode, registered it, and set it up as a systemd service so it survives reboots.
- Wrote a terraform-plan.yml workflow that automatically runs terraform plan on every push, using a Gitea Actions secret to inject the Proxmox API token.

## Issues / Findings
- The Gitea LXC could ping other devices on the LAN but not the internet after setting a static IP, turned out to be a missing default gateway/DNS in the network config, not a firewall issue.
- Learned that Terraform on Proxmox works by cloning a pre-built cloud-init template rather than installing from an ISO each time, that template is now reusable infrastructure, not a one-off.
- Had to think about the organization of secrets, kept the Proxmox API token out of git entirely (gitignored .tfvars locally, Gitea Actions secret for CI). Ran into a token formatting issue that broke the first CI run before I got the syntax right.
- actions/checkout@v4 doesn't work with a host-mode Gitea runner, it's a Node-based action expecting a container runtime, which host mode doesn't have. Replaced it with a manual git clone step using a repo-scoped access token instead.
