# September 5, 2026

## Worked On
- I wanted to get a backup system for my PostgreSQL database on my Debian vm.
- In my n8n workflow I added and configured two stripe node to update customer names.

## What I Did
- I had to create a new folder for my backup files to stay.
- In the pve web dashboard I added a new virtual disk to my VM which used my backup ssds storage.
- Once the new virtual disk was added I mounted the folder to that disk.
- A .sh file was created to execute a script that generates a .dump file with a date and time in the file name.
- I then added a cron job to run the .sh file each night and once done it will add the process to a log file.
- For n8n I added two stripe nodes, for the first one it was a "Get Many Customers" action which was paired with my stripe credentials. The node gets my current customers and filters for the specific client that booked by matching emails.
- The next node is to Update a Customer, so once the customer gets found the node then updates the customer in strip with the name of the client that booked an appointment.

## Issues / Findings
- n8n had some issues with running commands for my pg_dump, since n8n lives in a container and has limited access to the VMs filesystem.
- I had to setup a .sh file to send the pg_dump file to a specific folder and then I also added a cron job to run that .sh file and log it when complete.
- There was some trial and error when setting up the "Get Many Customers" and "Update a Customer".
- Within each node I had to make sure the data fields were checking and grabbing the right info from my main webhook and stripe.
- For a couple of the data fields, the way I initially had them configured the node was grabbing every customer and updating every customers name. So I had to make sure the node was getting the proper email address and then only updating that customers name.
